# v0.1.0-alpha.3

> Date: 2026-04-29
> Status: Windows atomic-write fix release
> Supersedes: `v0.1.0-alpha.2`

## Why This Release Exists

Windows testing of `v0.1.0-alpha.2` passed `typecheck` and `build`, but `pnpm test` exposed a FileStore write issue:

- `rename(temp, run.json)` can throw `EPERM` on Windows when the destination is briefly locked.
- The failed replacement can cascade into `run.json` read failures and false run failures.

## Fix

- FileStore replacement now retries transient Windows replace errors with short backoff.
- If Windows replacement remains blocked and the destination exists, it falls back to retrying copy-overwrite and best-effort temp cleanup.
- The copy fallback is intentionally Windows-only and best-effort; it trades atomicity for avoiding failed run mutations when rename is blocked.
- Added regression tests that simulate Windows `EPERM` without requiring a Windows host.

## Expected Windows Flow

```text
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

Then continue with the fake Runtime smoke test in `WINDOWS-TEST-RUNBOOK.md`.
